#1: Critical Delimiter Marked Non-Special: '<|im_start|>'

SEC-TOK-004
File: tokenizer.json | SHA-256: 492ebf55999f2a71...16f9d76c | Methodology: Tokenizer Configuration AST & Special Flag Inspection
Consumer Impact: CONFIRMED PROMPT INJECTION VULNERABILITY: The control token '<|im_start|>' is configured with special=false. Any end-user can include '<|im_start|>' in their prompt to bypass system instructions, forge assistant responses, or hijack multi-turn chat sessions.

Deterministic Reproduction Walkthrough

  1. 1. Open tokenizer manifest 'tokenizer.json'.
  2. 2. Inspect entry for control delimiter token '<|im_start|>'.
  3. 3. Note declared attribute: 'special: False' (Expected: true).
  4. 4. Dry-run Tokenizer test: Pass input containing raw delimiter string in user prompt turn.
  5. 5. Observation: Tokenizer emits special control token ID 128039 instead of literal text tokens.
  6. 6. Consequence: The LLM runtime interprets this as a structural role boundary tag, allowing prompt breakout.
Raw Proof Metadata
{
  "token_id": 128039,
  "content": "<|im_start|>",
  "special_flag": false,
  "normalized_flag": false,
  "lstrip": false,
  "rstrip": false
}
Remediation: Update 'tokenizer.json': Set 'special: true' for token '<|im_start|>' to ensure user inputs are properly escaped by the tokenizer.
